# 네이버 메일 정리 플러그인 0.1.0

Gmail용 정리 프롬프트를 네이버의 폴더 방식에 맞춰 변환한 개인용 플러그인 패키지입니다. 받은메일함의 **읽은 메일만** 기존 분류 사례를 참고해 정리합니다.

## 현재 제공 상태

- 업로드 가능한 루트 plugin.json과 분류 스킬이 포함되어 있습니다.
- Python 표준 라이브러리만 사용하는 IMAP MCP HTTP 서버와 테스트가 포함되어 있습니다.
- 네이버 계정 연결, 서버 배포, 실제 메일 이동, ChatGPT 업로드 및 예약 실행은 아직 검증되지 않았습니다.
- 기본 ZIP에는 mcp.json이 없습니다. 실제 원격 주소가 없으므로 가짜 연결 주소를 넣지 않았습니다. 업로드 직후에는 스킬만 제공하며 실제 네이버 도구는 생기지 않습니다.
- 서버 배포 후 configure_endpoint.py로 주소를 검증하고 mcp.json을 추가해 다시 압축하면 연결 정보를 포함하는 패키지가 됩니다. 또는 ChatGPT의 맞춤 MCP 연결에 배포한 서버를 직접 등록할 수 있습니다. 계정·관리자 정책에 따라 연결과 무인 쓰기 승인이 제한될 수 있습니다.

## 원본 프롬프트와의 대응

| Gmail 동작 | 네이버 구현 |
|---|---|
| 현재 사용자 라벨 참고 | 운영자가 허용한 현재 실제 메일함 조회 |
| 기존 분류 사례 조회 | 각 분류 메일함의 최근 사례 조회; 필요 시 본문 조회 |
| 읽은 받은편지함 메일 | INBOX의 SEEN, UNDELETED 조회 |
| 라벨 하나 적용 후 보관 | 기존 목적지 폴더 하나로 UID MOVE |
| 다른 분류 라벨 제거 | 네이버 폴더 구조에 해당하지 않아 수행하지 않음 |
| 다른 사용자 라벨 유지 | 네이버에 Gmail 복수 라벨 동작을 흉내 내지 않음 |
| 읽음·별표·중요 유지 | 플래그 변경 명령을 보내지 않음; 네이버 고유 중요 표시 보존은 실계정 확인 필요 |
| 애매한 메일 보류 | INBOX에 그대로 유지 |
| 기존 보관 메일 | 읽기 전용 참고 |
| 삭제·라벨 변경 금지 | 삭제·폴더 생성/이름 변경/삭제 도구 자체를 제공하지 않음 |

메일함 allowlist는 안전한 대상 제한용입니다. 분류 시 이름이 존재하는지 다시 확인합니다. 분류함이 새로 생기거나 이름이 바뀌면 서버 설정도 갱신해야 합니다. 계정 하나당 서버 인스턴스 하나를 사용하며, 두 계정은 별도 인스턴스·인증정보·데이터 경로로 연결하세요. 공용 다중 사용자 서비스로 배포하는 용도가 아닙니다.

## 네이버 준비

1. PC 네이버 메일 → 환경설정 → POP3/IMAP 설정 → IMAP/SMTP 설정 → 사용함.
2. 네이버ID에서 2단계 인증 설정 후 애플리케이션 비밀번호 생성.
3. 기존 분류 메일함의 정확한 이름 확인. 프로그램이 새 메일함을 만들지는 않습니다.

IMAP 서버는 imap.naver.com:993이며 TLS 인증서를 검증합니다. SMTP 발송은 사용하지 않습니다.

## 서버 실행

Python 3.11 이상 또는 Docker가 필요합니다. 서버는 네이버 IMAP으로 나가는 TCP 993 연결과 지속 저장 경로를 지원하는 환경에서 실행해야 합니다. 기본 ChatGPT Sites 호스팅은 raw TCP를 지원하지 않으므로 이 서버를 그대로 올릴 수 없습니다. 별도 서버의 선정·배포는 이 패키지에 포함되지 않습니다.

1. server/.env.example을 개인 설정 파일로 복사하고 실제 값을 넣습니다. 완성된 설정 파일은 절대 ZIP에 넣거나 ChatGPT에 첨부하지 마세요.
2. NAVER_HANDLE_KEY와 MCP_API_TOKEN은 서로 다른 충분히 긴 무작위 값으로 만듭니다.
3. NAVER_CLASSIFICATION_FOLDERS에는 실제 기존 메일함 이름을 JSON 배열로 넣습니다.
4. NAVER_ALLOW_MOVE=false를 유지해 먼저 미리보기로 확인합니다.

Docker를 사용하는 경우, 패키지 폴더에서:

```bash
docker build -t naver-mail-organizer ./server
docker volume create naver-mail-organizer-data
docker run -d --name naver-mail-organizer --restart unless-stopped \
  --env-file /absolute/private/naver-mail.env \
  -p 127.0.0.1:8080:8080 \
  -v naver-mail-organizer-data:/data \
  naver-mail-organizer
```

Windows의 Docker Desktop에서도 설정 파일 절대 경로를 해당 OS에 맞게 바꾸세요. 다른 방법으로 Python을 실행할 때는 환경변수를 프로세스에 주입한 뒤 `python server/server.py`를 실행합니다. .env 파일을 Python이 자동으로 읽지는 않습니다.

웹 ChatGPT에서 연결하려면 인증된 HTTPS 역방향 프록시 뒤에 /mcp를 노출해야 합니다. 로컬 HTTP 포트나 네이버 비밀번호를 인터넷에 직접 노출하지 마세요. Bearer API 토큰으로 인증하며 네이버 비밀번호는 MCP 호출 인자로 받지 않습니다. 토큰별 사용자 구분이 없는 개인 전용 서버입니다. HTTPS 설정·호스트 접근 통제·비밀정보 관리는 운영 환경에서 완료해야 합니다.

## 연결 정보를 포함한 ZIP 만들기

1. 서버와 HTTPS 연결을 실제 배포합니다.
2. 개인 환경변수 MCP_API_TOKEN을 설정합니다.
3. 패키지 폴더에서 `python server/configure_endpoint.py` 실행 후 실제 HTTPS /mcp 주소를 입력합니다.
4. 도구 목록 검증에 성공하면 루트 mcp.json이 생성됩니다. 비밀번호나 토큰은 기록하지 않습니다.
5. 전체 패키지 폴더 하나를 ZIP으로 다시 압축합니다. .env, 데이터베이스, 캐시, 인증정보는 제외합니다.
6. ChatGPT의 Plugins에서 개인 플러그인 업로드/가져오기 기능이 제공되면 해당 ZIP을 업로드합니다. 계정에서 ZIP 업로드가 노출되지 않으면 맞춤 MCP 서버 연결 기능을 사용합니다. 설치 화면의 정확한 경로는 계정과 관리 정책에 따라 다를 수 있습니다.
7. 인증정보 입력 화면에서 MCP_API_TOKEN을 제공하고 설치/연결합니다. 네이버 비밀번호를 채팅창에 입력하지 마세요.

이 단계는 도구 목록 존재만 확인합니다. IMAP 계정 접근 성공이나 메일 이동을 증명하지 않습니다.

## 반드시 수행할 연결 검증

일반 대화에서 플러그인을 선택한 다음:

> 연결 상태와 메일함 목록을 확인해줘. 받은메일함의 읽은 메일 최대 10건에 대해 기존 분류 사례를 참고한 분류안만 보여줘. 실제 이동은 하지 마.

결과가 맞으면 NAVER_ALLOW_MOVE=true로 바꾸고 서버를 재시작합니다. 테스트용 읽은 메일 한 건을 이동한 뒤 네이버 웹에서 목적지, 읽음·별표·중요 표시를 확인하세요. 이상이 있으면 이동을 비활성화합니다. 서버가 UID MOVE를 지원하지 않으면 작업은 실패하며 COPY+삭제로 우회하지 않습니다.

## ChatGPT 예약

연결과 실제 이동을 확인한 뒤 플러그인이 선택된 일반 대화에서 다음과 같이 요청하세요.

> 이 플러그인의 organize-read-mail 스킬을 사용해 매일 오전 9시(Asia/Seoul)에 네이버 받은메일함의 읽은 메일을 분류해줘. 예약 지침은 skills/organize-read-mail/references/scheduled-prompt.txt의 내용을 사용해줘. 먼저 현재 연결의 읽기 동작을 확인하고 예약을 생성해줘.

웹 예약은 연결 도구를 사용하므로 서버는 실행 시 접근 가능해야 합니다. ZIP 설치만으로 예약이 생성되지는 않습니다. 예약에서 실제 이동 권한이 허용되는지도 첫 실행으로 확인하세요. 연결 문제 또는 승인 요구가 발생하면 완료로 간주하지 않습니다.

기본 한 실행의 검토 상한은 200건입니다. 새 메일 중 읽지 않은 메일은 다음에 읽음 상태가 된 뒤 대상이 됩니다. 대상이 0건이고 오류가 없을 때만 조용히 종료합니다. 본문 20,000자까지만 분류에 제공하고 첨부파일은 분석하지 않습니다. 헤더는 PEEK로 읽으며, 본문 조회 역시 PEEK를 사용합니다. SQLite에는 이동한 계정/UID/목적지/시각만 저장하고 본문은 저장하지 않습니다. 다만 IMAP 본문 조회 시 전체 메시지 원문이 메모리로 수신되므로 대용량 첨부 메일이 많은 환경은 추가 크기 제한을 적용한 뒤 운영하세요.

## 검증 범위

`python -m unittest discover -s tests -v`로 로컬 테스트를 실행합니다. 테스트는 서명 위조, 참고용 메일 이동 금지, 미확인 메일 이동 금지, 목적지 제한, 미리보기, 중복 이동, PEEK 사용, 플래그 변경 명령 부재를 모의 IMAP으로 검사합니다. 네이버 실계정과 ChatGPT 예약에서의 통합 테스트를 대신하지 않습니다.
